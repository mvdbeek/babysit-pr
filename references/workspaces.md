# Experimental workspace overview

This opt-in internal module adds a **Workspaces** dashboard tab listing the local Git worktrees and herdr workspaces you are working in, the pull request or issue each one belongs to, and whether that item is still open. It can clean up selected workspaces in batches: exit their agents, close their herdr workspaces, remove their worktrees, and delete their local branches. It registers no watches, starts no agents, and pushes nothing. Its own API, background scan, bounded cache, JavaScript, and stylesheet keep its failures inside this experiment.

## Activation

Create `experiments/workspaces/config.json` under the dashboard's `--home` directory, then start your dashboard normally:

```json
{
  "enabled": true
}
```

Optional keys: `src` (the directory scanned for clones, `~/src` by default) and `roots` (extra clone paths outside it). Configuration is read at dashboard startup. The experiment does no scanning and no network work when disabled. The existing authenticated `gh` executable needs read access to the repositories you work in; `herdr` is read through its socket API.

## What is listed

Every **linked worktree** of a scanned clone is a workspace, joined with any herdr workspace whose checkout is that path and the agents running in it. A clone's own checkout is listed only while herdr holds it open, and can never be removed here — cleaning it up closes its herdr workspace and nothing else. A herdr workspace with no Git checkout, or one whose checkout no longer exists, is listed as well so it can be closed. Discovery is Git-first: paths, branches, heads, remotes, and branch upstreams come from `git worktree list` and the clone's shared config, never from a workspace label or a directory name. A clone whose config sets `core.bare = true` although it has a `.git` directory is skipped with all its worktrees, as Git lists no checkouts for it; the scan names it in a warning, with the `git config core.bare false` command that restores it.

Workspaces default to **Last updated**, newest first. **Sort by** also offers **Created**, and the direction button switches between newest and oldest first. Both dates appear below the workspace name. Creation comes from the first worktree HEAD reflog entry, falling back to the checkout's filesystem birth time when available. Updates follow HEAD reflog activity, checkout directory changes, modified or untracked file times (up to 1,000 paths), and the latest agent transcript in the checkout or its subdirectories. Git index and fetch times are excluded so routine inspection does not move a workspace to the top. Missing timestamps, including workspaces without a known checkout, sort last in either direction. The selected sort survives filtering and automatic refreshes while the page remains open.

The base repository is the `upstream` remote when one exists, otherwise `origin` or, when `origin` is a fork, its parent. That answer is cached for a day; a failed or budget-exhausted lookup is never cached as an answer.

With a machine registry (`--home/machines.json`, see the supervisor reference), every scan also lists each enabled worker machine's worktrees and herdr workspaces, read-only and marked with the machine's label. Each worker costs one ssh call per scan, which streams `scripts/remote_probe.py` to the worker's `python3 -I -S` (nothing is installed there, and no site hooks run) and reads its clones under its `src`, plus `herdr --machine=<label>` for its workspaces and agents. Its Git runs without hooks, fsmonitor, filter drivers (git-lfs included), textconv, external diffs, signature checks or fetching, does not look into submodules' working trees, and refuses a checkout whose config sets `core.worktree`. Its answer is read only up to 8 MiB, rejected unless every field type-checks (no non-finite numbers, plausible counts and times), and capped at 300 checkout rows and 300 workspace rows per worker; herdr's listings for it are rebuilt from type-checked fields the same way. The probe carries the scan's deadline and stops its own Git when it passes, even if the ssh client was killed. GitHub links are resolved here as for local rows, each worker getting an equal share of the requests this machine left. A worker whose answer cannot be turned into rows is treated as unreachable, and a cache that would grow past its limit is saved without workers' rows. This machine's rows are published as soon as they are complete; a worker's are merged in when it answers. A worker that does not answer within two minutes keeps its last rows, marked stale, and is not asked again for ten minutes, doubling with each further failure up to 80 minutes. **Diff** and **Transcript** read a worker's checkout there, the composer messages its agents and resumes its sessions there, and cleanup acts there (see below); opening its workspaces is not offered from here yet, and the server refuses it.

## Opening a workspace

The **Actions** column offers **Open workspace** for an existing herdr workspace and **Create workspace** for a checkout without one. Both open Collie in a new tab, with an **Open in Collie** fallback link if popups are blocked. Creation attaches a herdr workspace to the listed checkout without starting an agent or changing native focus. Existing agents are preserved. The action revalidates the listed checkout and shares the cleanup/creation lock so repeated clicks reuse the workspace instead of duplicating it. Errors appear beside the button and can be retried.

**Diff** and **Transcript** open a read-only viewer for a listed checkout, or for a row that is only a herdr workspace. The same viewer is offered wherever the dashboard links a herdr workspace to Collie (pull request, issue and watch rows, **Needs you** cards, the workspace dialog, launch results, scheduled tasks and Sentry issues being handled), and works there without this experiment. A watch reads its registered checkout even without a workspace, so a blocked repair's card and the watch's detail offer its transcript, opening on the session its repairs resume; with no workspace there is no agent to message. The diff shows the branch since its merge-base with the nearest remote base branch (the `upstream` or `origin` branch named like `main`, `dev`, `release_*` or `24.1` that the checkout is fewest commits ahead of), with uncommitted changes included and the commits listed. The **Base** menu offers the other candidates, and **Uncommitted only** compares the working tree with `HEAD`. Untracked files are listed by name, an untracked directory once. Each file is capped at 4,000 lines and the whole diff at 3 MB.

A worker machine's checkout (its Workspaces row, or a workspace ID qualified as `mini/w1`; never a disabled worker's) is read on that worker through the same streamed probe as its inventory: the server finds the checkout from its own inventory row or `herdr --machine=<label> workspace list`, never from the browser, and the worker checks it is the top of a Git checkout. The diff runs there with the same limits and Git hardening, which this machine's own diffs now share. The worker lists its sessions for the checkout (kept for 30 seconds), and a transcript is read only from a file in that listing: the worker returns its new complete lines, at most 4 MiB per call, and refuses any file outside its Claude `projects` and Codex `sessions` folders, not ending in `.jsonl`, reached through a symlinked folder or with a second hard link. Parsing happens here, as for local transcripts (a worker's lines over 4 MiB are skipped with a notice, a local one's over 64 MiB), so a replaced or truncated file is read again from the start. The composer works for a worker's agents as for this machine's, every herdr call going to `herdr --machine=<label>`: messages, stops, answers and dialog choices, and resumes, whose refusals use the worker's own facts (its panes, the session lease this machine holds for it, and whether the session's directory still exists there). A resume asks the worker's probe for its own paths (the checkout, its Git common dir, the session's directory, Claude's account home or Codex's home, and its babysit-bwrap), stages a message in a new private file under `~/.local/state/babysit-pr/message-prompts` there (pruned after a day), and types the resume line through the worker's own sandbox, with the account's `CLAUDE_CONFIG_DIR` as the worker spells it. It holds the worker clone's lock (see cleanup below) until its agent is typed, and is refused at once while a cleanup or launch holds it, rather than wait behind a removal. A closed workspace there is followed or reopened on the worker. **Docker access** is not offered for a worker's agents, and quitting when done is not available for them yet. Attached files are copied to the worker before the message is typed, into `~/.local/state/babysit-pr/attachments` there, and the message names the copies. An unreachable worker shows an error naming it in the viewer, and this machine's views are unaffected.

The transcript lists the Claude and Codex sessions whose recorded working directory is the checkout or one of its subdirectories, newest first, titled by their first prompt. It shows prompts and replies, with each tool call collapsed under its name and its output (failures marked) inside; reasoning and injected context are left out. Long texts are clipped, the newest 200 entries load first with **Show earlier entries** for the rest, and an open transcript fetches new entries every 10 seconds while its newest entries are shown, updating tool calls in place so opened ones stay open. Links in agent text, tool calls and commit subjects open in a new tab.

When the checkout has a herdr workspace, the viewer can also talk to its agent. Click a diff line to comment on it; comments appear under their lines and in the composer at the bottom, which also takes free-form follow-up instructions. **Send**, or Shift+Enter in the message box (where Enter starts a new line), submits one message (each comment with its file, line and quoted code, then the instructions) to the workspace's agent through `herdr agent prompt`, which types only into a recognized agent, never a shell. With several agents, choose one; a working agent receives it at its next turn boundary, and ordinary messages to one waiting on a question or approval are refused. Answer Claude and Codex questions directly in the transcript question card: select an option or type an answer, then submit. This uses the matching session’s visible question dialog, including Codex asynchronous requests that have already returned an acknowledgment. Free text uses Codex’s Other/notes field (or a free-form question). Other Claude dialogs of numbered options, such as permission prompts and plan approvals, show their text and one button per option; a click presses that option’s number key once the dashboard sees the same dialog still on the agent’s screen. Multiple-choice check boxes, open text fields and other unfamiliar dialogs still require Collie, and their screen preview opens at the bottom, where the dialog is. When herdr reports a Claude agent as waiting but its screen shows an empty prompt box and no dialog, the dashboard treats it as idle: **Send** pastes the message into the prompt box and presses Enter once it shows. If an answer was partly sent, finish it in Collie rather than submitting again. If herdr sees no reaction within five seconds the message counts as sent, with a warning to check Collie rather than resend. Control characters are removed before the text is typed, so a quoted diff line cannot act as keystrokes.

Beside the Diff and Transcript tabs, or on a line of its own below them when the viewer is too narrow, a transcript's header says whether an agent runs that session right now: **Live** with what it is doing (working, waiting for an answer, idle or done), or **Not running**. While an agent of the transcript's kind runs in the workspace with a session herdr cannot name, the header says **Status unknown** instead, since that agent may run this one. With workers registered it also names the machine, "this Mac" or the worker's label. A worker's sandboxed Claude records its session as `sessions/<pid>.json` by the PID it has in the sandbox, the same in every sandbox, which herdr cannot match. So babysit-bwrap gives each launch a `sessions` directory of its own, beside its broker's socket, and the broker (`worker_broker.py`) reports the session to herdr itself, as herdr's Claude hook would, once the session has a transcript in the launch's own store and again after a `/clear` or `/resume`. A worker's Codex is not reported yet and shows **Status unknown**. The workspace's other agents are listed below the header, each with a link to its transcript, and the session choice marks every session an agent runs. **Stop turn** appears while an agent works and sends Esc, which interrupts the turn and keeps the agent running. **Quit agent** ends the agent's process after an inline confirmation (`POST /api/workspace-quit` with `X-Babysit-Action: workspace-quit`, naming the workspace, pane and session). Under the pane's lock the server checks that the pane still runs that session as exactly one Claude or Codex process that the pane's shell started, and that the shell takes typed commands (a login or interactive shell, not `bash -c` or a script); quitting the pane's root process, or one that ends with the agent, would close the pane, so it is refused. A session a babysit watch owns or is handing off, an agent an exit watch quits by itself once its task is done (a message sent with **Quit the agent when it is done**, `wt --exit-when-done`, a scheduled task or a cron run), a scrolled terminal and a draft in the composer each refuse the quit before any key, so a draft is never lost. Quits, Docker access restarts, exit watches and handoffs share a lock file per pane under the state home (panes share a fixed set of 256 by hash, so an unrelated pane's exit may occasionally make one wait), and each checks the agent again once it holds it, so no two of them exit one pane's agent at once. While a quit holds it, the dashboard's other exit watches and scheduled launches wait for it, normally for a few seconds. A working agent, or one waiting on a dialog, then gets Esc and must settle idle as the same process on the same session, with an empty composer. Claude then gets a typed `/exit` and Enter, sent only once its composer shows exactly `/exit`, and Codex gets Ctrl-D. The quit counts as done only once the process has left; otherwise, including when herdr fails or times out after a key, the reader is sent to Collie. An exit is attempted once per process until the dashboard restarts, because a second key could reach the shell once the first one took. The pane's shell and the checkout stay, and the session can be resumed from the composer. Agents on workers cannot be quit from here yet: their **Quit agent** is disabled, and the server refuses it.

With workers registered, **Move…** beside a running Claude or Codex agent on this machine moves it to a worker, where it continues the same session in the same branch (`POST /api/workspace-move` with `X-Babysit-Action: workspace-move`; `pr_supervisor.py workspace-move <workspace> [--machine ID] [--yes]` does the same through the dashboard). An inline card first shows the server's plan: the branch with its unpushed commits, changed and untracked files, the machine Auto would choose (placed as New task places a launch, by labels, capacity and the repository's rules, never this machine and never a full worker) with the others to pick from, the processes the agent started (from `ps`), which exiting it stops, and the paths Git ignores that are not rebuildable (see below). A blocked agent, a draft in its composer, another agent in the workspace or another pane running anything beyond its shell (the workspace closes after the move), a pane root that is not an interactive shell, a scrolled terminal, a main clone's own checkout, a detached head, unresolved conflicts, submodules, a nested repository, Git LFS, an exit watch, a babysit repair and a babysit watch that resumes the session itself refuse the move before anything is sent, as does a worker whose probe finds no clone of the repository under its `src`, a branch or directory of that name already there, or no such Claude account. While a move runs, the dashboard refuses at once any message, stop, quit, resume or Docker change for that pane, session or checkout, rather than make it wait. A working agent moves only with the confirmation the card asks for, and its turn is stopped with Esc first; an agent that starts working again later in the move is never stopped without that confirmation, and the move fails before the exit instead. The branch's commits that the repository's default branch lacks (the `upstream` remote's HEAD, else a `main`/`master`/`dev`-like branch of `upstream` or `origin`), its index and its whole working tree (untracked files too; files Git ignores are not copied) travel as one `git bundle` over ssh, so a review of a pull request from a fork that only this clone has a remote for carries the fork's commits too, staged under `~/.local/state/babysit-pr/move-staging` on the worker and removed once read. The worker's probe checks the branch out in a new worktree of its own clone under its `src`, fetching that default branch from GitHub only when its clone lacks the commits the bundle builds on (a refusal names the missing commits and what each fetch said), setting the branch's upstream as it is here: through its remote naming the same repository, or a fork's remote it adds, named as `wtpr` names one (`wtpr-<owner>-<repo>`, by its GitHub URL, with its remote-tracking ref at the commit this clone's names). If that remote cannot be added, the branch is left without an upstream, the result and the agent's first message say so, and a move a babysit watch would follow is refused up front, since the watch matches a review checkout to its pull request by that upstream. A clone with no known default branch is refused before any key unless its whole history fits in a move. Only the agent's own children that run an MCP server (by program, script or package name) are counted as restarting with it rather than stopped, and answers the head, index tree and working tree it made; only when they equal this checkout's is the agent here exited, as **Quit agent** exits it. Its checkout is read again then, and a change since is sent once more. The transcript (Claude's subagent transcripts too), with the working directories it recorded moved to the new checkout, goes to the worker's store under the project folder Claude names after that checkout (or after the same folder below it, for a session started in one), or the Codex rollout's day folder, and the session is resumed there through the worker's sandbox with the same Claude account, model and effort, and a first message saying it was moved, from where to where, and that background jobs from before are gone. A babysit watch of the workspace still waiting for release is stopped for the move, so nothing resumes the session meanwhile, and registered on the worker for the resumed agent; it can only follow to a Linux worker and a clean worktree, and the move is refused otherwise. Once the worker's herdr shows the agent on that session, this workspace, its worktree and branch go through the cleanup below. Under the clone's lock, right before the workspace closes and again before the worktree goes, the move checks that the checkout still holds exactly what was copied, and lists what Git ignores there: rebuildable paths (`.venv`, `venv`, `node_modules`, `__pycache__`, `.tox`, the mypy, pytest and ruff caches, `build`, `dist` and the like) go with the worktree, but anything else keeps the worktree here, with the workspace closed and the paths named in the result. A checkout changed since its copy is kept too. A failure before the exit leaves the agent running here (stopped, if it was working) and removes the worker's new checkout; one after it keeps the checkout here, gives a held watch back, and names the command that resumes the session here. The card follows the move by its ID and says how it ended. Moves are saved under `<home>/moves`; a dashboard restarted during one marks it interrupted with the step it had reached and the command that resumes the session here, and gives back a watch it held.

**Move…** beside a running Claude or Codex agent on a worker moves it back to this machine, the only target offered for it (`POST /api/workspace-move` naming the worker's workspace as `<machine>/w1`; `pr_supervisor.py workspace-move <machine>/w1 [--machine local] [--yes]`). It is the same move with its sides swapped, and every check above applies on the side it concerns. The worker's herdr and probe read the agent, its pane and its checkout there: the probe answers the same checkout facts this machine reads of its own (`move_source`, the one implementation both sides run) and lists the agent's processes and its pane's shell with the worker's `ps` (`processes`). This machine must have room for one more agent, a clone of the repository at `~/src/<repo>` and the same Claude account, and the new worktree goes under `~/src/worktrees/<repo>`, checked by the same receive op a worker runs, here in a process of its own. A working agent is stopped with Esc through the worker's herdr. The worker's probe writes the bundle (`move_bundle`) and later a tar of the session's files (`move_pack`) into its own `~/.local/state/babysit-pr/move-staging`, a folder only its user can write; each comes back over ssh by its name alone, at most as large as a move takes, is checked against the size and SHA-256 the probe answered, and is removed there once read. The ops validate every argument: checkout paths must be a checkout's top, objects and the move's ID must be well formed, the base must be a branch of `upstream` or `origin`, and only a transcript in one of the worker's session stores is packed. Once this machine's checkout equals the worker's, the worker's agent is exited as a quit exits one there (a typed `/exit` for Claude, Ctrl-D for Codex, its pane's shell checked through the worker's `ps`). The transcript's recorded working directories move to the new checkout, it goes to this machine's Claude account store or Codex sessions, and the session resumes in a new workspace here, in this machine's sandbox (Safehouse on macOS), with the same account, model and effort (a Codex session's from its last turn when its command line names neither) and the same first message. A babysit watch of the worker's workspace still waiting for release follows it here; any worktree will do for a watch here. The worker's Docker access cannot be read from here, so the resumed agent starts without it. The worker's workspace, worktree and branch then go through the cleanup of its Workspaces-tab row, under the worker clone's lock, with the same checks of what changed or is ignored there, and the result says only that they went once the worker no longer has the checkout. A failure before the exit leaves the agent running on the worker and removes the new checkout here; one after it keeps the worker's checkout and names the `ssh -t <worker> '…'` command that resumes the session there. While it moves, the dashboard refuses at once any action on that worker's pane, session or checkout, named as the worker's own. Moving an agent between two workers is not offered.

When no agent is running there, usually because it exited after finishing, the composer offers **Resume and send** with a choice of the sessions recorded in the checkout, newest first. The agent's own resume command (`claude --resume <id>` or `codex resume <id>`) with the message as its prompt is typed into a new split of the workspace in the session's directory, never into an existing pane, whose shell might hold a half-typed line. The command is typed like a launch, so shell wrappers such as Agent Safehouse apply. A resume is refused while an agent runs in the workspace, while the session is open in any herdr pane, within two minutes of resuming it (until its agent shows up), and when a babysit watch owns the session (the picker marks those) or a babysit repair holds its lock, so one conversation never has two agents. For a session a babysit watch owns, the composer names the watch up front, links to it on the watcher tab and offers **Cancel watch and send**: after an inline confirmation, the server cancels that watch and, only if the cancellation took effect at once, checks the session lock and the queue again and resumes in the same request. A watch in the middle of a repair is never resumed over: its cancellation waits for the repair (**Cancel watch after this repair**), and the message is kept to send once the watch has stopped. Once the command is typed, any later trouble is reported as uncertain, never as not sent. A viewer left open while its workspace is closed keeps its checkout: it follows the one workspace opened on that checkout since (herdr gives a reopened workspace a new ID), never one that was already open beside it, and with none open, **Resume and send** reopens a workspace on the checkout and types the resume into its new shell. **Reopen in Collie** does the same without a message, so the session waits for the reader in Collie; for a session a babysit watch owns it reads **Cancel watch and reopen**, behind the same confirmation. A watch's own view (a blocked repair's **Needs you** card, or the watch's detail without a workspace) offers the composer on the watch's registered checkout, so its repair session can be taken over from there.

Unsent comments and text are kept in this browser per workspace and checkout, and a successful send clears only what it sent. Comments can be removed from the composer, and the diff takes the keyboard: Tab to it, choose a line with the arrow keys and press Enter to comment. Sending uses the same POST protections as other dashboard actions. The **Docker access** checkbox reflects the selected running agent's current Safehouse socket grants. Toggling it immediately quits and resumes the exact conversation in the same pane and directory with access enabled or disabled, without sending a message or clearing the dashboard draft. Supported launch options, including permission modes, are preserved. Restarting requires a verified idle agent with an empty terminal composer; busy agents, drafts, blocked dialogs, unknown launch options, changed identities, watcher-owned sessions, agents an exit watch quits by itself and another exit of the pane under way prevent the restart. Exit is attempted once per process; an unconfirmed exit requires inspection in Collie. Inspection uses macOS Seatbelt; unavailable access is shown as unknown and cannot be toggled. Access supplied by a custom policy without an explicit Docker integration must be changed in Collie. Sending never changes Docker access, and exited sessions resume with the shell's normal defaults. Docker itself is not started.

Requests name a herdr workspace or a listed row, never a path. For a herdr workspace, the checkout is the one herdr reports, which must be the top of a Git checkout, wherever it is. On the Workspaces tab, only rows the inventory scanned as Git worktrees offer the views. A session must be one listed for that checkout.

`POST /api/workspace-open` accepts a listed workspace `key` with the `X-Babysit-Action: workspace-open` header and the dashboard's usual origin protections. The server resolves the checkout and Collie URL; the client supplies no command or destination.

## How pull requests and issues are matched

A checkout is matched to the pull request and issue it belongs to, from evidence the repository agrees with (a name-derived pull request and a branch-derived one can both appear when they differ):

- The branch pushed to a fork: `head=<owner>:<branch>` against the base repository. A tracked upstream branch supplies its own owner and branch name, even when the local branch has been renamed (for example, a review cronjob's `review-pr-24342`). Tracking a base or release branch (`main`, `dev`, `release_26.1`, `25.0`) does not count as a head. The fork owner from `origin` is also tried with the local branch name. Local branches named like a base or release branch are never matched by head.
- A `wti`-style `issue-<number>` branch or directory name.
- A `wtpr`-style `pr-<owner>-<number>` directory or branch name, only when `<owner>` owns the resolved base repository.

Each result is shown with its state: **Open**, **Draft**, **Closed**, or **Merged**, linked to GitHub. A checkout with no match shows _None found_, and one whose lookup has not completed yet shows _Checking GitHub…_. Matching is a strong hint, not proof: a branch can be reused, and a fork can carry several pull requests for one branch (the newest wins). The 20 newest pull requests from a branch name, across all forks, are read at once; when other forks fill all 20, the owner's own pull request is looked up exactly instead.

Row status combines that with local state. **Ready to clean up** means every matched item is closed or merged and nothing blocks removal. **Open work** means at least one matched item is still open. **Needs an override** means something would be lost. **Protected** means the workspace can never be removed here.

## What blocks a cleanup

Local state is read without touching it: `git status --porcelain` for uncommitted changes, and `git rev-list HEAD --not --remotes --branches --tags` (excluding this branch) for commits no remote ref and no other local branch carries. Blockers are shown in the row and skipped during a batch unless the confirmation dialog's per-row **Remove anyway** override is ticked. That override approves exactly the conditions listed beside it: a condition that appears between confirming and removing — an agent that started writing, a change made in another terminal — stops the cleanup and is named in the result instead of being swept along with the tick. Counts may change freely; kinds may not. The blockers are:

- uncommitted changes, including untracked files
- commits only this branch has, which removal really would lose (100+ is a ceiling, not an exact count)
- an agent still `working` or `blocked` in that workspace
- local state that could not be verified
- a clone's own checkout, where only the herdr workspace is closed

Two conditions can never be overridden: a checkout an **unfinished watch** is using (cancel the watch in the Watcher tab first) and a herdr workspace whose checkout lies outside the scanned clones. Watches marked `closed` or `stopped` remain in history but no longer protect their checkout; paused, blocked, and running watches still do, including a repair finishing after cancellation. A cleanup target whose clone is not one the scan reaches is refused outright, however the request arrives, so the blast radius is never wider than the list. Everything recorded here is re-read immediately before anything is removed, so a stale selection is never acted on; a workspace that changed in the meantime is skipped or fails rather than removed on old evidence.

## What a cleanup does

Selected workspaces are cleaned up one at a time, under the same per-clone lock the PR workspace actions take, so a cleanup cannot race a workspace creation in that clone. For each one:

1. Every idle agent in the workspace is asked to exit (`herdr agent send-keys … ctrl+d`) and given up to five seconds. A working agent is never sent keys: approving its removal closes its workspace, which ends the pane. Agent transcripts are written as the agent runs and survive either way, but text typed into a pane and never submitted does not.
2. Each herdr workspace owning that checkout is closed, which ends its panes.
3. The worktree is removed with `git worktree remove` (`--force` when uncommitted changes or unknown state were approved; approving only a working agent keeps Git's clean check, so what it wrote before its workspace closed is kept).
4. The local branch is deleted with `git branch -D` when no commit can be lost — every commit is on a remote ref or another local branch, which is the normal state after a squash merge, where `git branch -d` would refuse. When local state could not be verified, the safe `git branch -d` decides instead, and a branch Git refuses to delete is **kept**: the result says so and the worktree stays removed.

A worker's row is cleaned up on that worker, never a disabled one. Its herdr listings are read again there (a listing that fails stops the cleanup), and one probe re-reads the row's clone, which must be among the worker's own scanned roots. Its agents and workspaces are reached with `herdr --machine=<label>`, and a second probe removes the worktree and branch: the worker checks again that the path is a worktree `git worktree list` names for that clone, neither its own checkout nor inside its Git directory, runs the clean check with its hardened Git unless uncommitted changes or unknown state were approved, deletes the tree without following any symlink in it before Git drops its registration, and deletes the branch only while that worktree had it checked out (a name starting with `-` is never deleted, here or there). A locked worktree (`git worktree lock`) is refused before anything is deleted. The per-clone lock is held on this machine, keyed by the machine and the clone's real path on the worker: the same lock the launches, resumes and scheduled agent tasks on that worker hold until their agent is typed. Once a cleanup holds it, the row is read again and skipped if anything changed meanwhile, on this machine too: approval is by kind of blocker, so a workspace or agent pane the first read did not show skips the row as well.

Clones, remote branches, transcripts, and the watcher queue are never touched. A failure stops that workspace and the batch continues with the next one; each result keeps its own status, message, and steps. Progress is in memory only: a dashboard restart during a batch loses the report, not the work, and the next scan shows what actually remains. One batch runs at a time, with at most 50 workspaces per batch; requesting another while one runs is refused, reported in the dialog, and leaves the selection intact. An unexpected failure is recorded against its own workspace and the batch continues.

## Refresh, limits, and failure states

The inventory is rescanned in a background daemon thread at most every five minutes, and **Refresh** brings the next scan forward by at most once a minute. While the tab is visible the browser reads the snapshot every five seconds. A scan runs `git status` and `rev-list` per checkout across eight threads, every checkout found, and spends at most 100 GitHub requests. Lookups are batched: one GraphQL request per base repository answers up to 50 head branches and issue or pull request numbers, and one head lookup serves every fork owner of a branch, so a full inventory usually costs a handful of requests. An exhausted budget leaves links stale rather than wrong, reports it once per cause, and fills them in on later scans; lookups never answered go before ones that merely expired, so none is starved. A number GitHub does not know fails only its own lookup. An open pull request or issue is cached for 15 minutes, a closed or merged one for six hours, and "no pull request found" for one hour, every entry the latest scan used plus up to 500 others (for checkouts that may come back) in a state file capped at 4 MiB, written `0600` through a temporary file and an atomic replace. Base repositories expire with their own day-long window, an old cache format is discarded safely, and a cache too large to persist is reported rather than dropped silently.

The last completed inventory and its observation time are saved in that same cache. After a restart, the first request shows those rows immediately. A snapshot less than five minutes old keeps its original refresh deadline; an older one is marked stale and refreshed in the background. As checkout checks finish, their updated rows appear without waiting for the slowest checkout. Only the completed scan is persisted. GitHub lookups are requested only when their individual cache entries are missing or expired, and base repository resolution is shared by all worktrees of a clone during a scan.

The snapshot is restored only when the configured scan paths match; older caches containing only GitHub lookups remain usable and acquire an inventory on the next scan. Cached rows are for display: opening and cleanup still revalidate current resources. Local Git checks remain periodic because a commit timestamp cannot reveal uncommitted edits.

Loading, stale results, an empty inventory, per-repository warnings, and API errors have separate messages. An unavailable herdr still lists worktrees, without workspace or agent information. A failed scan keeps the last inventory, including one restored after a restart, and marks it stale. Run one dashboard per state directory.

## Disable or remove

Set `"enabled": false` (or remove its config file) and restart the dashboard. This hides the tab and stops all scanning. The experiment directory can then be deleted without touching watcher, PR, or issue state.

To remove the code, delete `scripts/workspace_overview.py`, `assets/dashboard/workspaces.js`, `assets/dashboard/workspaces.css`, its two test modules, and this document. Remove the small integration hooks in `scripts/dashboard.py` (construction, injected server field, one endpoint, two POST actions, two assets), `assets/dashboard/index.html` (scripts/style, tab, panel, dialog), and the `workspaces` page entry/visibility event in `app.js`. It reuses the Git discovery helpers in `scripts/pr_workspaces.py` in one direction only; nothing in the watcher, overview, or workspace-action code depends on this module.

Validation uses temporary clones with real worktrees, fake herdr and agent executables, fake GitHub responses, isolated state directories, and temporary browser servers. Screenshots cover the desktop and mobile listing and the confirmation dialog. Run all checks with `uv run --locked tox`.
